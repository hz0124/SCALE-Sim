# ARGUS 重跑结果 (2026-06-15, 55/55 ok)

本轮在 06-13 基础上落了三处改动后**全量重跑**（原 06-13 数据未动，见 `../overnight_2026-06-13/`）。

## 0. 本轮改了什么

1. **#17 gate ×2 修复**：Bagel/Janus 都是 gated FFN（gate + up 两个同形状投影）。文本侧 `ffn_up` 此前只算了一个投影，已改为 ×2 周期 + 2× 能量（图像侧本就 ×2）。**影响所有 run 的文本阶段**。代码：`bagel_sim.py` / `janus_sim.py` `run_gen_text`。
2. **quant_proj 打开**（framework §15）：ARGUS 的 qkv/omap 投影权重量化 INT4 → 用满双阵列（图像解析宽 32→64、文本走新 `configs/bagel/ours_proj_int4.cfg` 32×64），能量按 W4A16（权重 0.5B）。**只对 ours 的基础对比（=完整 ARGUS）开**；消融档保持关。
3. **#16 系数核对**：`sram_*_pj_per_byte` 0.05→0.5（修 10× 节点缩放笔误，SRAM 占比 <0.5% 不动结论）；`w4a16=0.5` 仍是占位（临界 0.57，待 RTL 校准）；`coefficients.py` 顶部加了 §16 核对块。

口径同 06-13：**util = ΣMAC/(2048×cycles)**（分母含空闲子阵列），500 MHz，`--energy`。
原始数据：本目录 `summary.csv`（55 行）/ `summary.json` / `breakdown.csv` / `breakdown_4bucket.csv` / `logs/`（55 个）。

## C. quant_proj 边际贡献（= 完整ARGUS / 纯all_on）

| 模型/任务 | Δ加速 | Δ能效 | Δutil |
|---|---|---|---|
| bagel/GenEdit | 1.15× | 1.16× | +9.5 |
| bagel/GenEval | 1.14× | 1.15× | +9.1 |
| bagel/MM | 1.13× | 1.15× | +0.1 |
| **janus/GenEval** | **1.40×** | **1.35×** | **+17.6** |
| **janus/MM** | **1.59×** | **1.49×** | +0.2 |

**quant_proj 在 Janus 上贡献巨大（1.40–1.59×），在 Bagel 上 ~1.13–1.15×** —— 正是 §D 的机理：Janus 维度小（dim 2048、MHA）、投影主导 workload，投影从半阵列(32)→满阵列(64)收益最大；Bagel 投影占比低、图像 FFN 本就用满阵列，故 quant_proj 增量较小。

> MM 的 Δutil 几乎为 0 但加速/能效大涨：MM 是 DRAM 带宽受限（util 本就 ~0.5%），quant_proj 让投影 col-fold 减半（周期↓）但 MAC 总数不变，故 util 几乎不变而周期/能量显著降。

## E. 待办 / 风险

- **w4a16=0.5 仍是占位**（临界 0.57，决定 figna 能效是否跌破 ours）—— 待 RTL 后仿校准（框架 §16）。这是当前能量结论唯一的敏感点。
- **quant_proj 的建模忠实性**：当前假设 ARGUS 投影权重 INT4 量化对模型质量无损（属算法侧评估，需算法确认）；若不忠实需回退（开关默认关，回退只需 JSON 去掉 `quant_proj`）。
- **dram_idle_mw=100** 占总能 ~10%，rough 占位，全硬件一致，影响相对比较小。
- 消融的 `t1_hard` / `t2_hard` 开关语义同 06-13（t2_hard 为占位，SAU 开销未建模）。
- 下游待办（框架 §18–20）：batch / 上下文扫描（需求 6）、disagg（需求 9）、SenseNova（需求 2）。
